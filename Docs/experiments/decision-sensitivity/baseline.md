# Baseline verification

Generated by `BaselineTests`. The primary experimental baseline is the shipped data: Model B (`dispositions: respond`) with both S1.6 fixes (`means: end`, and `minute: 0` on the four scripted events of the lived day). Model A is selected by `Baselines.ModelA()`, which restores the three settings the data had before, and nothing else.

## 1. What the shipped data now runs

| Setting | Where | Model A (before) | Primary baseline (now) |
|---|---|---|---|
| How traits and values enter a want | `decisions.json`, `deciding.dispositions` | `standing` (absent; code default) | **`respond`** |
| How a walk is credited to a want | `decisions.json`, `deciding.means` | `want` (absent; code default) | **`end`** |
| When the lived day's scripted events happened | `backstory.json` p01-p03, `morning.json` opening | no minute (-1) | **p01 0, p02 0, p03 0, m000-open 0** |

The shipped content validates with every validator the slice has. The code defaults in `DecisionDynamics` are unchanged (`standing`, `want`), so a rule file that names neither still runs Model A; the shipped one names both.

## 2. Model A is still there

`Baselines.ModelA()` differs from the shipped content in the three settings above and nothing else: every other decision number, rule list, profile and event is the same object or the same value. It runs (80 decisions on `daniel_ate_it` seed 1, against 72 under the primary baseline, and not the same ones).

**It is the runtime that shipped before the change, decision for decision.** Every decision of 15 mornings (the five design conditions, seeds 1-3: minute, person, act, room, leading want, urgency, resolution and margin) hashes to `3e544cc8f2be569d`, the value the same fingerprint took on the data as committed at `dd9065c`, loaded directly. Every test written before the change now selects Model A explicitly (34 fixtures), so every document they generate is expected to regenerate byte-identical.

## 5. The stale memory is not reintroduced

Memories of the lived day with no minute, held by anybody at the end of the five design mornings (seed 1): Model A **75**, primary **0**.

Leo's wish to find out, mean urgency over his decisions, first ten minutes against the last ten (`daniel_ate_it`, seeds 1-10): primary 0.378 -> 0.087; the same dispositions with the events untimed (S1.6's B) 0.459 -> 0.459. S1.6 reported 0.38 -> 0.09 under M1 on its design seeds.

## 6. S1.6's behaviour is reproduced exactly

S1.6 measured its recommendation as a condition built in code, `B timed end` (`S16.Conditions`). Built from Model A the way S1.6 built it, it runs **every decision of 25 mornings (1853 decisions) identically** to the shipped data: the same act, minute, room, leading want and urgency, resolution and margin to the last bit, and the same portions left. The same seed gives the same morning. S1.6's own experiment and held-out tests go on building their six conditions from Model A, so their documents and numbers are unchanged.
